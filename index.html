00使用说明与合规红线Rules of Engagement & Legal Boundary

⚠ 先读这一章，再动任何一台设备。本文件包含大量具备实际破坏力的攻击手法与命令。所有测试必须在获得书面授权、明确范围、明确时间窗、明确应急联系人的前提下进行。未经授权对计算机信息系统实施扫描、侵入、获取数据、干扰功能，在中国及绝大多数司法辖区均构成违法犯罪。

0.1 中国大陆适用法律（红线清单）

法律法规与本项目相关的条款要点红线
《刑法》第 285 条非法侵入计算机信息系统罪；非法获取计算机信息系统数据、非法控制计算机信息系统罪。情节严重处 3 年以下，特别严重 3–7 年。禁止
《刑法》第 286 条破坏计算机信息系统罪（删除/修改/增加/干扰，造成系统不能正常运行），后果严重 5 年以下，特别严重 5 年以上。禁止
《刑法》第 287 条之一/之二非法利用信息网络罪、帮助信息网络犯罪活动罪（提供工具、账号、技术支持）。禁止
《网络安全法》第 27 条不得非法侵入他人网络、干扰网络正常功能、窃取网络数据；不得提供专门用于侵入/非法控制的网络程序工具。禁止
《数据安全法》《个人信息保护法》测试过程中接触到的个人信息、重要数据必须脱敏、最小化使用、不得外传；数据分类分级与出境规则。强约束
《关键信息基础设施安全保护条例》若被测对象属关基（CII），测试需报主管部门；每年至少一次检测评估。强约束
《网络安全等级保护条例》/ 等保 2.0定级备案、建设整改、等级测评、监督检查；三级系统每年测评一次，四级每半年一次。对齐
《网络产品安全漏洞管理规定》不得在厂商提供修补措施前发布漏洞信息；不得向境外机构提供未公开漏洞信息。强约束

0.2 测试前必须完成的 6 件事

  1. 书面授权书：盖公章，明确委托方、受托方、目标资产清单、测试类型、时间窗、签署人。模板见附录 A。
  2. ROE（测试规则）：明确允许/禁止的技术、破坏性操作审批流程、紧急叫停机制。模板见附录 B。
  3. 应急联系人表：委托方技术负责人、安全负责人、法务、机房值班、我方项目经理，7×24 可达。
  4. 备份与回退证明：被测系统全量备份已验证可恢复并留存校验值；虚拟化环境保留快照。
  5. 隔离与白名单：测试源 IP 在 WAF/IPS/封禁系统加白；确认不影响第三方（云厂商、运营商、邻网）。
  6. 证据链与保密：建立证据保全目录（截屏、抓包、日志、哈希），签署 NDA，明确数据销毁时间点。

0.3 绝对禁止清单（任何情况下不得做）

  • R-01对未列入授权范围的 IP / 域名 / 无线信号做任何探测（含 ping、DNS 查询）。邻近租户、路人热点只做被动记录，绝不触碰。
  • R-02对生产系统执行拒绝服务类测试（SYN Flood、Slowloris、CC、放大反射），除非 ROE 逐项书面批准且有熔断机制。
  • R-03对生产客户端做 Deauth / 解除认证洪水。WiFi 的 DoS 验证一律放在实验室镜像 SSID 或屏蔽笼中。
  • R-04明文导出、外传、留存真实生产数据（尤其个人信息、口令、密钥）。取证用最小化样本并脱敏，结束按约定销毁。
  • R-05使用真实恶意样本 / 勒索软件在靶机落地运行。改用 EICAR、Atomic Red Team 或自写无害 PoC。
  • R-06在被测环境留下持久化后门。如需验证驻留能力，用一次性可撤销方式并登记，结束 100% 清理复核。
  • R-07修改生产数据、删改业务记录、篡改账务/订单/库存。只读优先，写操作必须单点审批。
  • R-08把发现的漏洞信息发布到公开渠道，或在厂商修复前扩散。遵循《网络产品安全漏洞管理规定》。
  • R-09测试员私自留存客户凭据、拓扑、源码。凭据交密钥管理系统，项目结束清除本地副本。
  • R-10社会工程测试中外发真实钓鱼链接、欺骗高管转账演练等，须单独审批并有人事/法务在场。

0.4 风险等级与文档使用约定

严重

可直接导致核心资产失陷、域控/生产库沦陷、大面积数据泄露、业务长时间中断。7 日内修复或临时缓解。

高危

可被利用于提权、横向移动、绕过关键认证，但需一定前置条件。30 日内修复。

中危

信息泄露、配置不当、缺失防御纵深，单独利用影响有限但可串联。90 日内修复。

低危 / 建议

最佳实践差距、加固建议、可观测性缺口。纳入下一迭代。

1.4 黑盒 / 灰盒 / 白盒

黑盒

零先验，模拟外部攻击者。最真实但耗时最长、易漏深层逻辑问题。适用：外部暴露面、首次摸底、合规。

灰盒 推荐

提供普通账号 + 基础拓扑，模拟"员工被钓鱼后的攻击者"或恶意内部人，性价比最高。适用：绝大多数内网与服务器测试。

白盒

开放源码、架构、凭据。覆盖率最高，可发现设计层缺陷。适用：关键系统发布前、代码审计。

1.5 风险量化口径

CVSS v4.0
基础分（攻击向量/复杂度/权限要求/用户交互/影响）+ 威胁分（在野利用成熟度）+ 环境分（资产重要性、缓解措施）
EPSS
未来 30 天被在野利用的概率。优先级 = CVSS × EPSS × 资产权重，避免"高分低危"挤占排期
CWE
弱点类型编号（如 CWE-89），用于归类与开发侧整改
VEX
漏洞可利用性交换：声明"本部署下该 CVE 不可利用"，减少无效告警
业务风险
可能性 × 影响 × 可达性。同一个"中危"在域控上是严重，在一次性测试机上是低危
注意：报告里不要只给 CVSS 分数。董事会看不懂 7.8 分意味着什么，但看得懂"一个前台页面的漏洞，可以在 40 分钟内拿到全部客户数据并加密生产库"。每条严重/高危都要写清业务影响和攻击耗时。

4.4 明文协议与"古老但仍在跑"的服务

以下服务在太多内网仍在使用，且几乎全是明文或有已知缺陷：必须逐项确认是否真的需要，不需要就关掉。
  • NP-01HTTP / FTP / Telnet：全明文 → 替换为 HTTPS / SFTP / SSH
  • NP-02SNMP v1/v2c：community 常为 public/private → 改 v3（authPriv）或关闭
  • NP-03LLMNR / NBT-NS / mDNS / WPAD：广播解析是 Responder 的温床 → GPO 关闭
  • NP-04SMBv1：永恒之蓝一族 → 全禁用；SMB 强制签名与加密
  • NP-05LDAP 匿名绑定 / 明文 LDAP → 禁用匿名，强制 LDAPS 与签名
  • NP-06NFS / rsync 无认证导出：showmount -e 检查 no_root_squash
  • NP-07VNC / RDP 弱口令与无 NLA：强制 NLA + 账户锁定
  • NP-08Redis / MongoDB / ES / Memcached 未授权访问 → 直接数据泄露或 RCE
  • NP-09IPMI / BMC / iLO / iDRAC 暴露在业务网段 → 独立管理网 + 强口令 + 固件更新
  • NP-10Docker Remote API (2375) 未授权 → 直接拿下宿主机

06中间人、广播协议与认证中继MITM, Broadcast & Auth Relay

这是内网失守最常见的第一步：攻击者什么都不用破解，只要在同一个广播域里"答应"客户端的询问，就能拿到 NTLM 挑战响应，进而中继到服务器或离线暴破。

# 监听 LLMNR/NBT-NS/mDNS 并响应
sudo responder -I eth0 -wrfv
# 拿到 NTLMv2 后：1) 离线暴破
hashcat -m 5600 hash.txt wordlist.txt
# 2) 直接中继（无需破解！）
sudo ntlmrelayx.py -tf targets.txt -smb2support -socks -c "whoami /priv"
sudo ntlmrelayx.py -t ldap://dc01.corp.local --escalate-user attacker
sudo ntlmrelayx.py -t ldaps://dc01.corp.local --dump-domain
#测试项黑客手法判定标准风险
MM-01LLMNR / NBT-NS 投毒客户端广播询问时抢答并索取 NTLM 认证GPO 关闭多播名称解析与 NBT-NS；改用 DNS严重
MM-02NTLM 中继（SMB）中继到未启用 SMB 签名的服务器执行命令全网 强制 SMB 签名与加密严重
MM-03NTLM 中继（LDAP）中继到域控写入 ACL / 添加用户 / 拉域数据LDAP 强制签名 + 通道绑定；仅 LDAPS严重
MM-04IPv6 劫持（mitm6）伪造 DHCPv6 下发恶意 DNS（Windows 默认优先 IPv6）未用 IPv6 则禁用；网络侧 RA Guard严重
MM-05ARP/DHCP 中间人 + SSL Strip截获后 sslstrip 降级 HTTPS → HTTP全网 HSTS（含 preload）；DNS/DHCP 防护高
MM-06WPAD / PAC 劫持抢答 wpad，把浏览器代理指向攻击者禁用 WPAD；固定 PAC 或 GPO 代理高
MM-07mDNS / SSDP / WS-Discovery打印机、投屏、IoT 广播发现被滥用做反射与探测跨 VLAN 阻断广播；终端防火墙限制中
MM-08强制认证（Coercion）PetitPotam / PrinterBug / ShadowCoerce：让服务器主动回连禁用相关 RPC 或限制；启用 EPA；SMB 签名阻断中继严重
MM-09证书服务中继（ADCS）中继到 HTTP 证书注册接口（ESC8）换 TGTADCS 启用 EPA；关闭 Web Enrollment 或强制证书认证严重

6.2 接入后的中间人

  • MM-10接入访客 WiFi 后能否直接访问内网管理口（路由器、防火墙、打印机、监控）
  • MM-11接入后能否 ARP 欺骗截获同网段其他客户端流量（验证客户端隔离 / PVLAN）
  • MM-12能否通过 DNS 劫持把用户导向钓鱼页（Evil Twin + 假门户）
  • MM-13内部站点是否强制 HTTPS 且 HSTS；是否可被 SSL Strip 降级
  • MM-14是否存在内网明文传输的凭据（Basic Auth、HTTP 登录页、明文 FTP/Telnet）
一句话总结：关闭 LLMNR/NBT-NS + 强制 SMB 签名 + LDAP 签名与通道绑定 + 禁用无关 IPv6 + HSTS，能一次性砍掉内网 70% 的"低成本失守路径"。这五项应放进第 29 章最高优先级。

11服务器主机安全基线（Linux / Windows）Server Host Hardening

"服务器稳不稳、会不会被黑"，八成取决于基础配置。本章按 CIS Benchmark / DISA STIG / 等保 2.0 口径，给出可逐条打勾的核查清单。

11.1 Linux 主机核查清单

  • LX-01系统与内核：版本是否在支持期；禁用不必要模块（dccp / sctp / rds / tipc / n-hdlc / bluetooth）
  • LX-02内核参数：ip_forward=0、icmp_echo_ignore_broadcasts=1、rp_filter=1、accept_source_route=0、accept_redirects=0、log_martians=1、tcp_syncookies=1、randomize_va_space=2、protected_hardlinks/symlinks=1、yama.ptrace_scope
  • LX-03SSH 加固：PermitRootLogin no、PasswordAuthentication no、PermitEmptyPasswords no、X11Forwarding no、MaxAuthTries 3、AllowUsers/AllowGroups、弱算法禁用、fail2ban
  • LX-04账户与认证：无空口令；UID 0 仅 root；口令复杂度与有效期；sudo 组实名且需密码；无 NOPASSWD 滥用
  • LX-05文件权限：/etc/shadow 000/600；无全局可写文件；无未授权 SUID/SGID；umask 027
  • LX-06服务最小化：逐项确认 enabled 单元；关闭 avahi / cups / rpcbind / nfs / telnet / rsh / vsftpd / xinetd
  • LX-07强制访问控制：SELinux Enforcing 或 AppArmor 启用且策略有效
  • LX-08主机防火墙：默认拒绝入站；仅开业务端口；规则持久化
  • LX-09日志与审计：auditd 关键事件；日志外发集中平台（本地日志可被删）；留存 ≥ 180 天
  • LX-10更新机制：补丁流程与周期；关键漏洞 72 小时内响应
  • LX-11启动完整性：GRUB 密码、单用户保护、Secure Boot、AIDE/Tripwire、rkhunter/Lynis
  • LX-12容器与命名空间：不以 root 运行容器；userns-remap；不用 --privileged
  • LX-13敏感文件：磁盘无明文密钥/口令；~/.bash_history；/tmp 权限
  • LX-14时间同步：chrony/ntp 指向内部可信源；时间偏移告警
  • LX-15Core Dump：生产限制 core dump（可能含内存中的密钥）

20密码学、TLS 与 PKICryptography / TLS / PKI

密码学很少"被攻破"，绝大多数事故来自用错、配错、密钥管错。测试原则：不审自研算法（禁止自研），只审算法选择、参数、实现、密钥生命周期与协议配置。

20.1 传输层（TLS）

编号检查项验证方法与通过标准
TL-01协议版本禁用 SSLv2/v3、TLS 1.0/1.1；最低 TLS 1.2，对外网服务建议启用 TLS 1.3
TL-02套件与参数禁用 RC4/3DES/DES、NULL、EXPORT、CBC + MAC-then-Encrypt 优先修复、禁用静态 RSA 密钥交换；优先 ECDHE + AES-GCM/ChaCha20-Poly1305；必须前向保密（PFS）
TL-03证书有效性有效期 ≤ 398 天、域名匹配（含 SAN）、非 SHA-1 签名、RSA ≥ 2048 / ECDSA ≥ P-256、非自签（对外）
TL-04证书链与信任链完整、无不受信根、无过期中间证书、配置 OCSP Stapling
TL-05重定向与 HSTSHTTP→HTTPS 全站 301；HSTS max-age≥31536000; includeSubDomains；建议加入 preload
TL-06弱点扫描testssl.sh / sslscan 全项；通过：无 HIGH 及以上，BEAST/LUCKY13/POODLE/FREAK/Logjam/DROWN/ROBOT 全绿
TL-07内部流量内网是否已 TLS 化（东西向）——内网明文是横向移动与嗅探的主要温床；至少对认证、数据库、管理通道加密
TL-08证书透明度是否监控 CT log 发现仿冒证书（防止域名被冒名签发）
TL-09客户端校验移动端/客户端是否正确校验证书（禁 trustAllManager、禁 hostnameVerifier 全通过）；是否可绕过证书固定（pinning bypass）
TL-10密钥交换与后量子是否启用混合后量子密钥交换（X25519MLKEM768 等）；制定 PQC 迁移路线（NIST FIPS 203/204/205）

20.2 存储与算法

编号检查项验证方法
CR-01口令存储必须用 Argon2id / scrypt / bcrypt / PBKDF2（高迭代）；禁止裸 MD5/SHA1/SHA256（加盐也不行）；每用户独立盐
CR-02对称加密AES-GCM/ChaCha20-Poly1305（AEAD）；禁止 ECB 模式（经典：ECB 企鹅图）、禁止静态 IV 的 CTR、禁用 DES/3DES/RC4
CR-03随机数敏感用途（token/会话/密钥/盐）必须 CSPRNG（/dev/urandom、secrets、SecureRandom）；禁止 rand()/Math.random() 或时间戳做凭证
CR-04密钥管理密钥不进代码/镜像/日志/备份明文；使用 KMS/HSM；轮转周期明确（对称 ≤1 年、签名 ≤2 年，且泄露可即时轮转）
CR-05硬编码密钥全仓扫描（gitleaks/trufflehog），含历史提交；命中即高危，必须轮换而非删除
CR-06完整性关键数据/文件/更新包是否有签名或 HMAC 校验；是否存在可篡改的更新通道
CR-07Padding Oracle是否暴露解密错误差异（"填充错误" vs "明文错误"）；CBC 场景重点测
CR-08敏感数据残留日志/错误信息/URL/Referer/缓存中是否出现明文密码、身份证、手机号、卡号、Token
CR-09国密合规（如适用）涉及国内合规场景需评估 SM2/SM3/SM4 落地与双证书体系，避免"自造国密"

20.3 PKI 与证书服务（含 AD CS）

编号检查项验证方法
PK-01CA 私钥保护离线根 CA、HSM 存储、最小可访问人数、双人控制

22数据安全、备份与勒索韧性Data / Backup / Ransomware Resilience

安全测试的最终命题不是"能不能进来"，而是"进来了会损失多少、多久能恢复"。本章与第 23 章稳定性共同构成"业务连续性"证据链。测试方法：假定已被攻陷，验证数据是否被加密、被外传、能否恢复。

22.1 数据分级与流转

编号检查项验证方法
DA-01资产与分级是否有数据资产清单 + 分级（公开/内部/敏感/核心）；敏感字段是否打标
DA-02最小化收集是否存在"收集了但不用"的敏感字段（常见：身份证、人脸、精确位置）
DA-03存储加密敏感字段落库是否加密/脱敏；密钥是否与数据分离
DA-04展示脱敏列表/导出/日志/客服后台是否脱敏（手机号/证件/卡号/地址）
DA-05导出与下载批量导出是否有审批、水印、限流与审计；测：低权限能否导出全量
DA-06外传通道是否有 DLP/出网管控；演练：模拟向外部网盘/邮箱/自建域名外传，是否被发现
DA-07测试环境数据测试环境是否使用生产真实数据（高危），是否脱敏

22.2 备份有效性（"没验证过的备份 = 没有备份"）

编号检查项验证方法与通过标准

BK-04加密备份静态加密 + 密钥独立保管（否则勒索者拿到密钥一并加密备份）
BK-05恢复演练每季度至少 1 次真实恢复演练并计时；记录 RTO/RPO 实测值 vs 目标值
BK-06覆盖度是否覆盖：数据库、对象存储、配置/IaC、密钥、证书、身份系统（AD/IdP 是恢复链条中最容易被忘的一环）
BK-07监控备份失败是否告警到值班人（不是"静默失败"）

HX-06DMA 攻击Thunderbolt/PCIe 直连内存读取；测：内核 DMA 保护、Thunderbolt 安全级别、端口物理管控
HX-07冷启动 / 内存残留测：是否全盘加密、休眠文件是否保护、是否禁用休眠
HX-08虚拟化逃逸测：VMM/Hypervisor 补丁、设备直通风险、嵌套虚拟化的隔离

26.3 其他值得列入年度测试计划的前沿方向

后量子密码迁移

NIST FIPS 203/204/205 已定稿。测：是否完成加密资产清点、是否在 TLS 启用混合密钥交换、长期保密数据的"先收割后解密"风险评估。

量子/随机数与熵源

嵌入式与虚拟化环境熵不足导致密钥可预测；测：启动早期熵、/dev/urandom 可用性、VM 克隆后密钥重复。

卫星 / 5G / 车联网（如涉业务）

测：GNSS 欺骗与干扰、5G 伪基站、NESAS/SCBA 合规。

浏览器与端点新攻击面

Unit 42 报告强调浏览器已成为主要入口（约 48% 事件涉及）。测：浏览器扩展管控、企业策略、下载管控、隔离浏览。

身份优先（Identity-first）

约 90% 事件涉及身份问题。测：非人身份（NHI/服务账号/API Key）清单与轮转——这是 2026 最容易被忽略的资产。

可观测性即控制

OWASP 2025 已将 A09 改为"日志与告警失效"。测：不只问"有没有日志"，而问"出事时会不会有人被叫醒"。

29加固基线与验收标准Hardening Baseline / Acceptance

29.1 服务器（Linux / Windows）基线

类别基线要求

29.2 网络与边界基线

  • HB-01公网入口收敛：必须有 WAF/反向代理/负载均衡统一入口，禁止业务机直接暴露公网
  • HB-02管理口（22/3389/管理后台）不直接对公网；必须经 VPN/堡垒机 + MFA
  • HB-03分区分域：办公网 / 生产网 / 测试网 / 访客网 / IoT 网隔离，跨区需审批与审计
  • HB-04出网白名单；DNS 走内部可控解析；禁止服务器任意出网
  • HB-05高危端口全网不可达（详见附录 D）
  • HB-06DDoS 防护与带宽冗余；有应急预案与演练记录
  • HB-07无线：WPA3（或 WPA2-AES + 强口令）、关闭 WPS、访客网独立且隔离、管理后台强口令 + HTTPS、固件在维护期内
  • HB-08安全设备规则季度评审；删除"临时放行"规则
  • HB-09网络配置变更有审批与回滚；有配置备份与 diff

29.3 应用与数据基线

  • HA-01全站 HTTPS + HSTS；内网敏感链路同样加密
  • HA-02安全响应头齐全（CSP、X-Frame-Options/XFO 或 frame-ancestors、X-Content-Type-Options、Referrer-Policy、Permissions-Policy）
  • HA-03Cookie：Secure + HttpOnly + SameSite；会话有超时与轮换
  • HA-04输入校验 + 参数化查询 + 输出编码 + 上传白名单（类型/大小/重命名/非 Web 目录/不执行）
  • HA-05认证：抗钓鱼 MFA 可选可强制、口令加盐慢哈希、登录失败限流、找回流程防枚举
  • HA-06越权：所有接口服务端鉴权（禁止只靠前端隐藏），对象级权限校验
  • HA-07错误处理：统一错误页，不回显堆栈/SQL/路径/版本号
  • HA-08依赖：SBOM + 漏洞扫描进 CI；高危依赖阻断合并；锁文件与私有源
  • HA-09密钥/证书：统一托管、定期轮转、到期前 30 天告警、禁止硬编码
  • HA-10数据：分级分类 + 脱敏 + 导出审批 + 外传管控 + 日志不留敏感明文
  • HA-11日志与告警：安全事件（登录失败、越权、异常导出）有告警且有人响应
  • HA-12发布：灰度 + 可回滚；安全测试通过才允许上线（门禁）

  • 日志被清空或 history 被禁用
  • CPU 长期异常（可能是挖矿）
身份与网络层
  • 非常用地/非常规时间的管理员登录
  • 短时间内大量登录失败后成功（爆破成功）
  • Kerberoasting / AS-REP 特征（大量 TGS 请求、RC4 加密票据）
  • 从未出现过的外连域名、IP、User-Agent
  • DNS 异常长标签 / 高频子域查询（隧道/DGA）
数据层
  • 非工作时间的大批量查询/导出
  • 数据库出现未知账号或权限变更
  • 备份任务被禁用、快照被删除
  • 压缩/加密工具异常调用（7z、rclone、gpg）
AI / 供应链层
  • AI 助手执行了未授权的命令或外发了数据
  • CI 流水线出现未知步骤、runner 异常
  • 依赖包版本在无人提交的情况下变化
  • lockfile 被 PR 静默修改
